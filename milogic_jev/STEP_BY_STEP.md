# Поэтапная реализация всех классов Milogic-Jev

## Этап 0. Подготовка

1. Иметь доступ к модели типа Jev (или любому API, которое принимает `state` + типизированные вопросы и возвращает калиброванные ответы).
2. Использовать оркестратор из `core.py`.

Файлы:
- `milogic_jev/core.py` — основные классы
- `docs/milogic_jev_classes.md` — таксономия
- `docs/milogic_jev_implementable.md` — схемы

## Этап 1. Монада как шаблон (самый быстрый путь)

Даже если модель не знает тип `monad`, его можно собрать из стандартных вопросов.

### Шаги
1. Для каждой двойственности создать 4 вопроса через `MonadQuestionBuilder.as_jev_questions()`:
   - choice — доминирующий полюс
   - score — сила замыкания (0–10)
   - noul — порождает ли следующий уровень
   - choice — тип отношения
2. После ответа собрать `MonadAnswer` через `from_jev_answers()`.
3. Применять правило: если `closure >= 0.78` и `generates_higher_level == true` → предлагать следующий уровень.

## Этап 2. Иерархический каталог с 2–3 уровнями

### Шаги
1. Определить L0 — базисные монады.
2. Определить L1 — вопросы, которые смотрят на результаты L0.
3. Добавить условие перехода.
4. Запустить через `HierarchicalCatalog.evaluate()`.

Пример уже есть в `build_belyaev_core_catalog()`.

## Этап 3. Правило замыкания и предложение следующего уровня

После каждого уровня проверять монады. Для сильно замкнутых вызывать `GenerativeCatalog.suggest_from_monad()`.

## Этап 4. Смена системы отсчёта

Создать 2–4 разных набора вопросов. Прогнать через `ReferenceFrameEvaluator`. Сравнивать уверенность.

## Этап 5. Генеративный каталог

Накопить корпус успешных монад. Генерировать формулировки следующего уровня по шаблону «по образу и подобию». Проверять стабильность.

## Этап 6. Многоуровневое состояние

Хранить state как словарь уровней. Вопросы могут указывать target_levels.

## Этап 7. Калибровка и статистика

Логировать монады. Считать, какие типы двойственностей дают стабильно высокий closure.

## Этап 8. Полный цикл

1. Формулировать базисную двойственность → L0
2. Оценить через Jev
3. Если замыкание сильное → предложить L1
4. Оценить L1 с учётом результатов L0
5. Сохранять успешные переходы

## Что уникального

- Встроенное замыкание вместо внешней композиции
- Монада как первоклассный объект
- Ограниченность роста как явное правило
- Преемственность по подобию
- Поиск инварианта через несколько систем отсчёта

## Следующие конкретные шаги

1. Подключить реальный вызов Jev вместо mock.
2. Собрать 5–10 двойственностей из текстов Беляева.
3. Зафиксировать устойчивые замыкания.
4. Уточнить пороги.
