# Новые классы систем принятия решений на основе Jev + Милогия

## Введение

**Jev** = плоский каталог типизированных вопросов (Noul / Choice / Score), параллельно оцениваемых против одного `state`, с калиброванными вероятностями.

**Милогия** = иерархия двойственных отношений (монад), которые замыкаются в новые уровни «по образу и подобию», с оболочками, подоболочками, субординацией/координацией и ограниченностью уровней.

Ниже — все основные новые классы, подвиды и варианты.

---

## Класс 1. Иерархический каталог вопросов (Hierarchical Question Shells)

Вопросы организованы в оболочки. Ответы нижней оболочки становятся частью состояния для верхней. Композиция встроена в структуру каталога.

### Подвиды
- **1.1. Жёсткая иерархия** — уровни заранее заданы, нижний всегда выполняется первым.
- **1.2. Динамическая иерархия** — новый уровень создаётся только при высокой вероятности замыкания.
- **1.3. Вложенные оболочки** — каждый вопрос может содержать подоболочку вопросов.

---

## Класс 2. Монадные вопросы (Monad Questions)

Новый примитив, которого нет в стандартном Jev. Вопрос всегда описывает двойственное отношение и возвращает структурированную монаду.

### Поля ответа
- `pole_a`, `pole_b`
- `dominant`, `dominance_probability`
- `closure` (0.0–1.0)
- `generates_higher_level`, `higher_level_confidence`
- `relation_type`: complementary | antagonistic | transitional | unstable
- `suggested_next_level` (опционально)

### Подвиды
- **2.1. Статическая монада** — полюса заданы заранее.
- **2.2. Открытая монада** — модель сама предлагает второй полюс.
- **2.3. Мультимонада** — несколько связанных двойственностей оцениваются вместе.
- **2.4. Монада с временной динамикой** — сравнение отношения между двумя состояниями.

---

## Класс 3. Генеративные каталоги (Generative / Evolutionary Catalogs)

Каталог не задаётся полностью снаружи. Система порождает кандидатов для следующего уровня по правилу преемственности.

### Подвиды
- **3.1. Преемственность по подобию** — аналоги работающих вопросов уровня N для уровня N+1.
- **3.2. Генерация через замыкание** — при высоком `closure` автоматически создаётся вопрос следующего уровня.
- **3.3. Эволюционный отбор критериев** — несколько формулировок прогоняются, остаются лучшие по калибровке.
- **3.4. Ограниченный рост** — явное правило на максимальное число подоболочек.

---

## Класс 4. Системы смены системы отсчёта (Reference Frame Search)

Один и тот же `state` прогоняется через несколько разных наборов критериев. Система ищет ту систему отсчёта, в которой ответы наиболее стабильны.

### Подвиды
- Параллельный перебор
- Инвариантный поиск
- Адаптивная система отсчёта

---

## Класс 5. Композиционные системы с явным замыканием

Композиция ответов происходит по правилам замыкания:
- `closure > threshold` → результаты сливаются в новый атомарный элемент
- низкий `closure` → композиция запрещена
- типы замыкания: интеграция, дифференциация, переход в новый уровень

---

## Класс 6. Многоуровневое состояние (Multi-Level State)

`state` сам имеет иерархическую структуру. Вопросы могут адресоваться к конкретному уровню.

---

## Класс 7. Калибровка двойственностей

Специализированная система, настроенная на оценку устойчивости и замкнутости двойственных отношений, с накоплением статистики.

---

## Класс 8. Гибридные системы

- **8.1.** Jev + внешняя иерархическая оркестрация
- **8.2.** Монада как композиция стандартных вопросов (Choice + Score + Noul)
- **8.3.** Двухконтурная система (внутренний контур оценки + внешний контур проверки соответствия принципам иерархии)

## Рекомендуемый минимальный реализуемый набор

1. **Монадный вопрос** (как шаблон поверх обычного Jev или как новый тип).
2. **Иерархический каталог с 2–3 уровнями** и явным переходом результатов вверх.
3. **Правило замыкания**: если `closure > 0.8` и `generates_higher_level == true`, автоматически создавать заготовку вопроса следующего уровня.

Этого достаточно, чтобы получить систему, структурно отличающуюся от плоского Jev и напрямую использующую ключевые идеи милогии (двойственность, замыкание, иерархия оболочек), оставаясь при этом реализуемой.
